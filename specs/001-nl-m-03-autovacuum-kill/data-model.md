# Data Model: NL-M-03 Autovacuum Worker Killed

Runtime records (evidence in `results.json` facts and the ledger), not database schema --
except the harness-owned table in E5.

## E1. KillTarget (adapter -> orchestrator -> injector)

| Field | Type | Rule |
|---|---|---|
| pid | int | process to kill |
| parent_pid | int | our postmaster; the kill is refused if the process's parent differs |
| title_marker | str | substring the process command line must contain ("autovacuum worker") |
| relation | str | relation being vacuumed when observed (evidence) |
| wraparound | bool | anti-wraparound vacuum (evidence) |
| observed_after_s | float | time from dead-tuple generation to observation |

## E2. KillCycle (one per repeat cycle)

| Field | Type | Rule |
|---|---|---|
| cycle | int | 1..5 |
| attempts | list[KillTarget + outcome] | outcome in {landed, changed_nothing}; max 3 |
| landed | bool | true only if a target's death was confirmed from /proc |
| death_confirmed_s | float | as NL-C-01 |
| postmaster_survived | bool | restart_after_crash path vs unit restart |
| recovery_s | float | first successful write after the kill (existing per-cycle recovery) |

State: `establishing -> target_found -> (changed_nothing -> establishing)* -> landed -> recovered`;
no target within the wait bound -> run aborted; 3 x changed_nothing -> run aborted.

## E3. VacuumEvidence (one per eligible relation, from verification)

| Field | Type | Rule |
|---|---|---|
| relation | str | schema-qualified |
| first_eligible_at | timestamp | first sample where dead tuples > its threshold |
| threshold | float | per-table option or global formula |
| last_autovacuum | timestamp/null | read after final recovery |
| vacuumed | bool | last_autovacuum not null AND >= t_recovered |

Aggregates -> measures: `relations_eligible` (count), `relations_left_unvacuumed` (count of
vacuumed = false; NOT_MEASURED if relations_eligible == 0), `autovacuum_worker_respawned`.

## E4. ObservedSettings

`autovacuum`, `track_counts`, `autovacuum_naptime`, `autovacuum_max_workers`,
`autovacuum_vacuum_cost_delay`, `autovacuum_vacuum_cost_limit`, `autovacuum_vacuum_threshold`,
`autovacuum_vacuum_scale_factor`, `restart_after_crash`, `update_process_title`.
Read once in init; disclosed; never written. Derived: `bound_s = 3 x naptime`,
`worker_wait_s = 2 x naptime + 30`.

## E5. Harness table `resilience.avac_target`

Narrow rows (id bigint, v int), ~1M rows, seeded once (reused while size matches), table-level
autovacuum options chosen so its vacuum lasts seconds. Dead tuples generated by the harness per
cycle and once at verification. Kept between runs and reseeded only when its row count
differs (live validation 2026-10-06: reseeding before every baseline put a checkpoint's spread
writes inside the measurement window).

## Measures added to the catalog

`kills_landed`, `autovacuum_worker_respawned`, `relations_eligible` (reported),
`relations_left_unvacuumed`. Reused: `cycles_run`, `cycles_recovered`, `rpo_txn`,
`indeterminate_txn`, `rto_first_write_s`, `starts_unattended`, `corruption_count`,
`structural_integrity_errors`.
